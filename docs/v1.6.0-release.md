# v1.6.0 — Dream Flow

## Executive result

Home reads more continuously in the rendered comparisons. The process leads into
one finished kitchen; its trailing photograph opens into broader inspiration;
the photographs settle into navy and the existing warm invitation. These are
static compositions, with no new transition animation or generic component.
The practical Budget threshold and the approved opening retain their roles.

Implementation started from clean `9c351a837bacce227ed9131e4d12c75b58f62ba1`
on `codex/v1.5.1-kitchen-expression`. Remote verification confirmed that v1.5.1
was not merged into main. The new branch is `codex/v1.6-dream-flow`.

## Signature 1 — Process → Projects

**Before:** a prominent warm conclusion/navigation panel, another background,
a broad Projects heading, then the photograph.

**After:** optional process detail sits quietly on the outgoing copy datum.
The finished photograph arrives beside the answering heading on the same paper
plane as the process journey. At 1440px its left edge is the process photo's
112px datum, its width is 681px, and the process aside/project heading align at
879px within 0.02px. The project photo starts 380px earlier in the whole page.
The process journey itself retains its complete height and breathing room.

**Implementation:** local outro styles; one article containing the heading,
photograph and project caption; a desktop grid sharing the process's 56% photo
plane. Newsreader carries the process's editorial voice into the answering
heading. Location, name, description and case-study navigation remain intact.

**Mobile:** an inset copy edge continues from aftercare through the optional
link and next heading. The photograph and its complete caption follow in DOM
order. No desktop overlap is applied to the content.

**Reduced motion:** the same paper surface and copy/photo alignment connect
the complete static process chapters to the finished project. The handoff does
not depend on the sticky process canvas.

**Iteration:** two composition passes, including a precise desktop datum repair.
The large boxed process conclusion was rejected as another stopping point.

## Signature 2 — Projects → Montage

**Before:** the project photo finished, a neutral interval followed, then a pale
section announced itself with an eyebrow and a heading repeating the same idea.

**After:** a pale shoulder approaches beside the photo's trailing edge, then
widens into the montage field. Longleys Road remains one warm, named case-study
caption, distinct from the broader photographic possibilities. The montage has
one heading and begins directly after the proof composition.

**Implementation:** a scoped, non-interactive backing plane aligned to the
project image edge; no duplicate photograph, new component or altered GSAP.
Responsive `sizes` reflects the project's measured new width; candidates and
loading strategy are retained.

**Mobile:** the pale field begins beneath the whole caption rather than as a
partial side bar. Photograph, caption and montage retain a common outside edge.

**Reduced motion:** the project retains its photograph and named caption, then
the pale shoulder leads into the complete six-image static montage. The project
and inspiration remain distinct without horizontal motion.

**Iteration:** three visual passes. The first mobile shoulder produced narrow
bars midway down the caption; the first tablet photo left an empty pocket.
Those treatments were rejected. Explicit grid sizing keeps the photo inside
its column while letting it finish with its caption on tablet.

## Signature 3 — Montage → Closing

**Before:** photographs ended above an empty pale interval, followed by a full
navy boundary and a separately introduced conversion composition.

**After:** navy begins behind the trailing photographs. In the static desktop
composition the dining image gets a complete 1200:780 landscape frame and a
shared bottom datum with the preceding photographs. Its right edge aligns with
the warm reassurance panel below. The panel arrives before the left invitation
has finished settling, giving the sequence an ordinary, useful destination.

**Implementation:** a static colour threshold behind the existing photographs,
a revised static second band, and scoped closing spacing. There is no image
fade, text overlay, masking surface or new animation. The main CTA remains
high contrast and the secondary About link gains a 44px touch target.

**Mobile:** a shallow 24px navy crossing, a clean full-width photographic ending,
and normal-flow copy and actions. The static collage retains all six images.

**Reduced motion:** the last static band gives the dining photograph its complete
landscape frame on desktop and aligns the photographs to a common bottom edge.
The navy crossing and warm invitation remain connected without animation.

**Iteration:** three rendered passes plus accessibility refinement. A narrow
mobile dining frame was constrained to its actual column; tablet's shorter
dining photo was aligned to the final row's bottom edge. A separate pale pause
was rejected because it retained the old restart.

## Motion

Montage timing is unchanged in the final implementation. A prototype moved the
desktop phase 30% of a viewport earlier while keeping travel distance and scroll
duration equal (`top 115%` / `bottom 30%`). It improved the dining image's arrival
but damaged the first photograph's viewing window. At the same 768px entrance
sample, its visible width fell from 55% to 2%; at 1440px, from 69% to 34%.
The experiment was rejected and reverted. Static composition was sufficient.
All motion source files and all five generated JavaScript bundles are identical
to the baseline.

## Performance

No dependency, image, duplicate transition image, global JavaScript or route
transition system was added. Static generation, hero priority, lazy imagery and
conditional motion loading remain intact. All 283 generated/public image files
are byte-identical; all five JavaScript bundles are byte-identical.

Only `sizes` descriptions for genuinely changed rendered widths were updated;
image candidates and formats are unchanged. Selected unique Home image bytes
are unchanged at 390px, increase 1.88% at 1440px/1×, and 2.03% at 1440px/2×.
This is the measured cost of matching the larger static photographic frames.
Final static output is about 19.66 MB; exact measurements are in the benchmark.
Core Web Vitals were not measured; no improvement is claimed.
