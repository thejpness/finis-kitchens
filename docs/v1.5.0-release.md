# v1.5.0 — Hidden Kitchen Architecture & Asset Optimisation

This release refines the approved commercial site, makes project content reusable
and bounds oversized image outputs. It retains the existing page compositions,
photographs, motion system, enquiry contract and protected story experience.

## Starting state and scope

- Starting branch: clean `main`, matching `origin/main`.
- Starting commit: `9b45fdde6147c44bb55cc8fef8d03b97f5684cce` —
  `feat: align services with v1.4 visual system`.
- Feature branch: `codex/v1.5-kitchen-architecture-optimisation`.
- Package manager: npm with the existing `package-lock.json`.
- Application release naming remains in this documentation; the starter npm
  package version remains `0.0.1`, following the established release convention.

Only commercial page styles, project data/templates, image generation and the
Astro dependency tree change. No source photographs or public assets were deleted
or replaced. No backend, deployment, shared layout, header/footer, font, global
token or motion-source changes are included.

`src/styles/commercial.css` is imported by normal pages and LegalLayout, with an
opt-in `.commercial` content wrapper. The wrapper applies no layout or global
typography. The protected story does not import this stylesheet or opt in.

The aliases reuse Home spacing, existing layout gaps, the existing 1px rules,
24px inset seam, small media radius and type scale. Compact indices and metadata
labels use `--fs-0` (14px); large stage numbers use `--fs-4` (26px). Metadata values
retain their existing readable page styles and gain wrapping guards. Existing
eyebrow roles remain unchanged. All undefined `--fs--1` references are removed
from normal-page consumers without adding a global token.

Editorial links share an underline, a 44px minimum height and visible keyboard
focus. Dark sections set their own existing light ink through local variables.
Buttons retain the established treatments and wrap within their available width.
There is no universal section component, fifth motif, decorative dimension,

## Project data and gallery

The existing Astro collection and Zod schema gain optional `heroAlt`,
`featureTeaser`, `featureHeading`, `featureParagraphs`, `featureLinkLabel`,
`introduction: { title, body? }` and `galleryHeading`. Gallery entries become
`{ image, alt, caption? }`, requiring a nonempty meaningful alternative for every
supplied photograph. New optional strings are trimmed and nonempty when supplied.
Longleys Road owns its exact former template/feature copy in frontmatter; the
Markdown narrative is unchanged. No project facts or specifications were invented.

New entries follow the existing `projects/<slug>/index.md` convention. A project
with only a title and narrative renders without empty optional modules. Generic
link/gallery wording and the established default social image cover missing
optional values. `featured` keeps its prior meaning and sort behaviour.

`src/lib/project-gallery.ts` resolves original dimensions at build time through
Astro's public image API attributes. Reading import metadata properties directly
can retain full originals in Astro output; using returned attributes avoids that
additional emission. There is no browser measurement or gallery script.

Adjacent non-panoramic images pair in their original aspect-ratio proportions,
giving equal photograph heights without cropping. Wide photographs (ratio at
least 1.8) stand alone; a solitary portrait is centred and capped at 38rem on wider
screens. Rows stack naturally below 48rem. DOM, reading and photograph order are
unchanged. Captions are rendered only when supplied and sit outside the image
motion wrapper. CSS grid fractions are normalised so single rows fill their slot.

The `sizes` hints describe the actual 48rem row transition, photograph share,
fluid container padding, row gap, 76rem maximum container and 38rem solitary
portrait. The touched homepage preview and Projects feature hints also reflect
their actual split compositions. Existing responsive candidate families remain.

Temporary projects validated missing optional fields, paired landscapes with a
caption, three portraits, a single portrait and the real mixed gallery. They were
removed before the final build. All built successfully and preserved natural
ratios and order at 390, 768 and 1440px. A no-photo homepage fixture confirmed that
the existing placeholder remains a necessary valid fallback; it is retained.

## Protected story regression gate

**`/the-love-that-stays` remains visually and behaviourally unchanged.**
Story markup/components/CSS, shared BaseLayout/PageLayout, header/footer, global
styles/tokens, motion source, fonts, public story images and PDF have no source
diff from the starting commit. Twenty-one protected emitted files, including
shared CSS, story CSS/JS, fonts, imagery and PDF, are byte-identical. Their hashes
are retained in the benchmark JSON. Commercial CSS is absent from the story.

Explicit baseline/candidate comparisons cover mobile 390×844 and desktop
1440×900, with both normal and reduced motion: initial presentation, open,
advance/back, close, focus return, transcript, typography, imagery and layout.
All four initial screenshots are pixel-exact. Some viewer edges/counter/native
disclosure pixels vary by at most two channel levels, over at most 288 pixels
(0.0222% of the desktop capture). Independently capturing the baseline twice
reproduces this edge antialiasing variation; no content or geometry changes were
observed. Viewer/transcript comparisons therefore do not claim every pixel is
byte-exact. Interaction checks pass in both modes and sizes.
